## Use When
- You want to identify performance bottlenecks after running the OpenEdge PROFILER.
- You have a `.out` file generated by `PROFILER:PROFILING = TRUE`.
- You want to know which source lines (and which methods) consume the most CPU time.

## Outputs
A Markdown table rendered directly in the chat, followed by a compact navigation
list with clickable file links for the top 5 unique source locations.

Columns:
- **#** - rank
- **Module** - class and method name
- **SrcLine** - exact source file line (corrected for include expansions via diff)
- **ActualSec** - exclusive self-time (does not include callees) - primary sort key
- **ExecCount** - number of times executed
- **AvgMs** - average ms per call
- **Source** - code snippet from that line

## Parameters
- `-ProfileFile` (required): path to the `.out` file.
- `-TopN` (optional): number of hottest entries to display. Default: `30`.
- `-Filter` (optional): substring filter on module/method name.
- `-SortBy` (optional): `actual` (default) or `cumulative`.
- `-ProjectRoot` (optional): workspace root for source file resolution. Default: current directory.
- `-OutputJson`: always pass this flag when running from chat - returns JSON for rendering.

## Instructions for the Agent

1. Find the most recent `.out` file under `.profile/` if the user does not specify one.
2. Run the script with `-OutputJson` and `-ProjectRoot` set to the workspace root.
   The script path is always `analyze-profile.ps1` inside the skill's **Base Directory**
   (shown when the skill loads, e.g. `C:/apps/MyApp/.devin/skills/analyze-oe-profile`).
   Use that absolute path - do NOT hardcode `.github/skills/...` since different agents
   mount skills under different folders (`.devin/skills`, `.github/skills`, etc.).

   **Important:** When invoking via `powershell.exe` as a child process, any `Write-Host`
   output from the child appears on stdout of the parent and will corrupt a direct pipe into
   `ConvertFrom-Json`. Use `Out-File` to capture JSON cleanly, then read the file:

```powershell
powershell.exe -NoProfile -File "<BaseDirectory>/analyze-profile.ps1" `
    -ProfileFile "<path-to-.out>" `
    -TopN 30 `
    -OutputJson `
    -ProjectRoot "<workspace-root>" | Out-File -FilePath ".profile/profile_analysis.json" -Encoding UTF8
```

   Then read the file with your agent's file-read tool and parse the JSON from its contents,
   skipping any non-JSON preamble lines before the opening `[`.

3. Parse the JSON array output. Each element has: `Module`, `LstLine`, `SrcLine`,
   `ActualSec`, `CumulSec`, `ExecCount`, `AvgMs`, `SourceCode`, `Uri`.

4. Render a Markdown table with plain line numbers (not links - links do not work in chat table cells):
   - Truncate `Module` to just `ClassName::MethodName` for readability (drop the repeated class name suffix OpenEdge appends).
   - If `SrcPath` is null (framework code), show `?` in the SrcLine column.
   - Show `SrcLine` as a plain integer. If 0, show `(overhead)`.

5. After the table, output a compact navigation list for the **top 5 unique source locations**
   (skip duplicate file+line entries). Format each entry as a backtick relative path
   followed by the line number as separate plain bold text:

   **#N** `relative/path/File.cls` line **NNN** - one-line description

   To compute the relative path: take `SrcPath` from the JSON (or derive from `Uri` by
   stripping the `vscode://file/` prefix), strip the ProjectRoot prefix and leading
   separator, convert backslashes to forward slashes.
   Example: `C:\apps\MyApp\src\myapp\OrderQuery.cls` -> `src/myapp/OrderQuery.cls`

   CRITICAL RULES for the links to work in chat (verified in Windsurf; other IDE chats behave similarly):
   - The path must be in backticks and be RELATIVE to the workspace root (e.g. `src/myapp/OrderQuery.cls`)
   - Do NOT prefix with `@`
   - Do NOT append `:line` or `#line` to the path inside backticks - this breaks linkification
   - The line number must appear as separate plain bold text AFTER the backtick path
   - If `SrcPath`/`Uri` is null (framework code), skip that entry

6. After the navigation list, add a brief analysis: which methods are the biggest bottlenecks
   and what type of issue each represents (N+1 query, duplicate detection, etc.).

## Notes
- `ActualSec` (exclusive) is the primary bottleneck signal; `CumulSec` reveals slow call chains.
- Line 0 = module load/init overhead; link opens the file without a line number.
- `SrcLine=0` for OpenEdge framework classes (no source available).
- Requires `git` on PATH for exact include-aware line mapping (falls back gracefully).
- Test/framework rows are hidden by default; pass `-ShowTestCode` to include them.

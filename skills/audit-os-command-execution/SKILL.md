## Use When
- You need an OS-command inventory for ABL code (`UNIX SILENT`, `OS-COMMAND`, `INPUT/OUTPUT THROUGH`, `DOS SILENT`).
- You need a platform compatibility report framed for a specific target OS (Linux/RHEL or Windows Server).
- You need unresolved dynamic command sites queued for AI review before the final report is opened.

## Outputs
- `os-command-inventory-latest.csv`: full inventory (source of truth). Includes `GatedFor` field indicating which OS each gated statement targets.
- `os-command-unresolved-latest.csv`: unresolved or low-confidence rows (`TokenConfidence < 75`).
- `os-command-audit-latest.html`: final interactive report generated only in the final reporting step, after AI review is complete.
- `command-decisions.xlsx`: client-facing decisions workbook (one row per unique non-baseline command). Generated by `-Mode command-summary` after AI review is complete.

## Required Outcome
- The task is not complete until the workflow runs to conclusion and produces a final HTML report.
- The final HTML report must open automatically in the user's browser only after both AI review passes are complete.
- The initial extraction run should not generate HTML.
- Do not treat the initial extractor pass as the final deliverable.
- If some command sites cannot be reasonably resolved, leave them unresolved, regenerate the unresolved CSV, and ensure the final report reflects that unresolved set clearly.
- This skill is for OS-command inventory and platform compatibility concerns. It is not a security scan and should not invent or overstate security-risk ratings.
- AI pass order is mandatory:
	1. unresolved command review (updates command fields and platform together)
	2. platform-only and gating review (rows still marked `PlatformClassification=unknown` OR `GatedFor=uncertain`)

## Workflow
1. Run the extractor on the requested roots to create the initial inventory and unresolved CSV only. Do not generate HTML in this step.
	This step also saves the audited roots as report context metadata for the final report.
2. AI Pass 1 (command-resolution pass): review unresolved rows from `os-command-unresolved-latest.csv` and apply updates directly into `os-command-inventory-latest.csv`.
3. During AI Pass 1, whenever a command token is resolved, update `PlatformClassification` in the same edit:
	- set `both` only when cross-platform is known with high certainty (for example OpenEdge utilities and explicitly known cross-platform tools)
	- otherwise set deterministic `windows` or `linux` when evidence is clear
	- if still uncertain, keep `unknown`
4. Leave rows unresolved when the command cannot be reasonably determined from available evidence.
5. Rebuild `os-command-unresolved-latest.csv` from the updated inventory using the unresolved filter (`CommandToken` blank or `TokenConfidence < 75`).
6. AI Pass 2 (platform-only pass): review rows where `PlatformClassification=unknown` after Pass 1 and update only platform classification fields.
7. Regenerate the HTML report with `-Mode report-only` using the final AI-reviewed inventory as the source of truth.
	The final report should reuse the saved audited roots from the extraction step so the HTML scope display remains correct.
8. The browser-opened report from the final `report-only` regeneration is the deliverable to the user. Do not end the task before this final report exists and opens.
9. Optionally, run `-Mode command-summary` after the final report to generate `command-decisions.xlsx` — a client-facing workbook with one row per non-baseline command. The client fills in `StillInUse`, `Action` (dropdown: `A-install / B-replace / C-deploy / D-dead-code`), and `ClientNotes`, then returns the file.
10. **Clean up generated scripts.** AI Pass 1 produces a PowerShell resolution script (typically placed in `devops/`). Once it has run successfully and the inventory CSV has been saved, delete that script — it is a one-time run artifact, not a permanent codebase file. Use the template at `<skill-dir>/pass1-resolutions-template.ps1` as the starting point for future passes.

## Browser Timing
- The report should open for the user only after both AI review passes are finished and the final HTML has been regenerated.
- The extraction step should not produce a report for the user.
- The user-facing completion point is the final HTML opened from the AI-reviewed inventory.

## Extractor Parameters
- Required: scope roots (`-Roots`) to scan. These are the directories the user asks you to audit.
- Optional: `-OutputDir` (defaults to workspace `docs`).
- Optional: `-TargetPlatform` (`linux` or `windows`, default `linux`). Determines which commands are flagged as concerns and which gated rows are suppressed as dead code.
- Optional: `-TargetPlatformLabel` (free text, default `RHEL 9.6`). Used in report title, HTML concern column header, and Excel Instructions sheet. Example: `Windows Server 2025`.
- Optional: `-WindowSystem` (`gui`, `tty`, or `any`, default `gui`). Declares the OpenEdge client windowing mode for the target deployment.
  - `gui` = prowin GUI client (default). Suppresses rows with `GatedFor=tty` as dead code. Applies to Windows GUI deployments and Linux Gnome/X11 OpenEdge GUI sessions.
  - `tty` = `_progres` character-mode client. Suppresses rows with `GatedFor=gui` as dead code.
  - `any` = do not suppress either mode.
  - **Important:** `TTY` in ABL `WINDOW-SYSTEM` means _character-mode interface_, not _Unix_. Both GUI and TTY sessions can run on Windows or Linux. Do not treat `GatedFor=tty` as equivalent to `GatedFor=unix`.
- `-Roots` should be passed as a PowerShell string array. Relative paths are resolved from the workspace root.

## AI Review Prompt (Use This)
For each unresolved row, trace in this order:
1. Full statement text.
2. Local variable assignments (both backward and forward).
3. Conditional branches (prefer unix-path value when split by OS).
4. Include files (`.i`) and macros.
5. Caller chain when values are passed in.
6. Best-effort inference from context if still ambiguous.

Update fields in the inventory row directly:
- If resolved: set `CommandToken`, `CommandSource=ai-context`, `OpaqueValue=False`, refresh `RHEL96Concern`, set `TokenConfidence`, recompute `ConfidenceScore`, and write concise `ConfidenceExplanation` with evidence.
- If resolved: also set `PlatformClassification` in the same update using best available evidence (`windows|linux|both|unknown`).
- If unresolved: keep `CommandToken` blank, set `TokenConfidence=0`, keep `ConfidenceScore=0`, and explain what was traced and why resolution failed.

When writing `RHEL96Concern`:
- Focus on portability, runtime dependency, command availability, wrapper-script dependency, path assumptions, platform-specific executables, or OpenEdge utility requirements relative to the target platform.
- Do not convert this field into a generic security rating or vulnerability assessment.

### AI Pass 2 Prompt (Platform-Only and Gating)
After AI Pass 1 is complete, review rows where `PlatformClassification=unknown` **OR** `GatedFor=uncertain`.

Update rules for Pass 2:
- For `PlatformClassification=unknown`: update only `PlatformClassification`. Do not rewrite already-deterministic rows.
- For `GatedFor=uncertain`: read the surrounding context (the full IF/THEN/ELSE structure) to determine which OS branch the statement is in. Set `GatedFor` to `unix` or `windows`. If the guard uses a negation (`OPSYS <> "..."`) infer the intended platform: `OPSYS <> "WIN32"` means `unix`, `OPSYS <> "UNIX"` means `windows`. If still genuinely ambiguous, leave `GatedFor=uncertain`.
- For `WINDOW-SYSTEM` guards: set `GatedFor=tty` when inside `IF WINDOW-SYSTEM = "TTY"` block, or `GatedFor=gui` when inside the ELSE branch (or `IF WINDOW-SYSTEM <> "TTY"`). **Do not set `GatedFor=unix` for a TTY gate** — TTY means character-mode, not Unix-only.
- Use `both` only when cross-platform support is known, not guessed.
- If evidence is still insufficient, keep `unknown` / `uncertain`.

## Notes
- The HTML report uses a Progress Professional Services gradient header with the Progress logo. The logo (`progresslogo.png`) is read at report generation time from the sibling skill folder `../analyze-abl-dependencies/templates/progresslogo.png` (relative to this skill's folder) — both skill folders must be copied together, side by side, whatever the skills root is. If the logo is not found, the report still generates but the `<img>` src will be empty.
- Stage 1 is deterministic extraction; Stage 2 has two AI passes (command-resolution pass, then platform-only pass).
- `os-command-inventory-latest.csv` is the source of truth after AI review.
- Keep `command-notes-config.json` current (`platformRules`, `basicUnixCommands`, `openEdgeCommands`, `commandNotes`, `commandNotes-windows`). The script selects `commandNotes-windows` when `-TargetPlatform windows` is used.
- Keep configuration guidance in `command-notes-config.md` (next to the JSON) so users can tune rules without script edits.
- **Ungated-risk rows** (orange left border in HTML report): rows classified for the opposite platform that have NO runtime gate (`GatedFor` empty). These will actively execute and fail on the target; they are the highest-priority items to address. Use the "Only ungated risks" filter toggle to focus on them.
- Platform classification starts with deterministic rules and writes `PlatformClassification` (`windows|linux|both|unknown`) to the inventory.
- During AI Pass 1, command-resolution edits must also set platform classification where possible.
- AI Pass 2 targets rows where `PlatformClassification=unknown` OR `GatedFor=uncertain`; deterministic or already-reviewed rows should not be re-checked in routine passes.
- `-Mode full` is extraction-only for this workflow and should not be treated as report generation.
- `-Mode report-only` refreshes the HTML report from inventory; it does not currently rebuild `os-command-unresolved-latest.csv`.
- When the user supplies more than one directory, pass them all in the same `-Roots @(...)` array in a PowerShell session, using the call operator (`&`) to invoke the script.
- If you are spawning a new PowerShell process, prefer `powershell -Command "& '...ps1' -Roots @(...) ..."` instead of `powershell -File`, so the array literal is parsed correctly.
- The extractor step saves audit context metadata so the final HTML can show the original audited roots even when `report-only` is run later.
- Re-extraction is required when upgrading an existing inventory CSV to include the `GatedFor` column — old CSVs without the column will have GatedFor suppression silently skipped in report-only mode. Run a fresh `-Mode full` scan to populate it.
- HTML filtering is for triage only; CSV remains the authoritative dataset.
- The final unresolved count should come from the regenerated unresolved CSV after AI review, so the user can find remaining unresolved items quickly.
- Unresolved rows must remain clearly marked by blank `CommandToken` and low confidence so they are easy to filter in both CSV and HTML views.

## Security & execution requirements

- **Execution capability**: This skill executes the bundled PowerShell script `generate-os-command-audit.ps1` (an unsigned local script) via `run-audit.cmd`; it reads ABL source files and writes CSV/HTML/XLSX reports. No database or network access.
- **Execution policy**: The invocation does not bypass PowerShell execution policy. The environment must permit local scripts (e.g. `RemoteSigned`, the Windows default). If execution is blocked by policy, stop and ask the user to adjust their policy consciously — never bypass it silently.
- **Safeguards**: the script is resolved only from the canonical skill directory (`<skill-dir>`) and verified with `Test-Path` before execution — missing script = stop. No PATH or current-directory fallback.
- **Supply chain**: the `ImportExcel` module (only for `-Mode command-summary`) is pinned to reviewed version `7.8.10` from PSGallery; see the Command Summary Run section above.
